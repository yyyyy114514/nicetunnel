# nicetunnel

多个 Cloudflare 免费账号共同承载的边缘代理 + 订阅系统。基于 [cmliu/edgetunnel](https://github.com/cmliu/edgetunnel)（GPL-2.0）重写控制面，协议实现逐字沿用上游。

和 edgetunnel 相比，主要解决"号多、人多"时的问题：

- **让每个号都被用上、不死薅少数号**：主站定时读取每个号当天的 Workers/Pages 请求数，订阅里每个节点用哪个号的域名，按"预计剩余额度 × 节奏"加权分配（加权 rendezvous 哈希，刷新前后尽量不变）。"节奏"= 按各号当前消耗速度推算到 UTC 0 点会不会用完：会剩的多分、会提前耗尽的少分，所有号趋向于在重置前同时用到预算；另有单域名占比上限（默认 25%）保证多样性。
- **轮询保证覆盖所有账号**：每个账号至少每 `cycleMinutes`（默认 15 分钟）轮询一次，账号多时每次的批量自动放大；多个 isolate/Cron 并发轮询时按账号合并结果，不会互相覆盖。
- **订阅刷新几乎不耗额度**：一次刷新 = 1 次请求；用量查询、规则列表、IP 段都由 Cron 后台分批更新；KV 写入有预算和限频（免费版每天 1000 次）。
- **优质 + 优选订阅 + 兜底三组节点可同时开启**：优质 = 自定义来源（如 gate 的住宅 SSTP 链式节点）；优选订阅 = 可设置多个优选 URL / 优选订阅生成器（IP 列表、CloudflareSpeedTest CSV、`sub://` 生成器、节点订阅），URL 里的 `{isp}` 按访问者运营商自动替换；兜底 = 随机优选 CF IP。
- **随机优选少超时**：节点池里一部分直接取自"优选订阅"里的已知可用地址（比例可调），其余按访问者运营商从对应 CIDR 抽取；同一份订阅里每个节点都在不同 /24、端口倾向 443；IP 池按时间窗渐进轮换（默认每小时换 25%），节点名稳定，客户端测速结果不会每次刷新都作废；Clash/sing-box 里自动选择组自带 `lazy` 测速，坏节点会被客户端自动避开。
- **内置订阅转换**：直接读取你的 subconverter INI（`ruleset` / `custom_proxy_group`），原生生成 Clash(mihomo)、Surge、sing-box、v2rayN/Shadowrocket 通用订阅，不再依赖第三方 SUBAPI。sing-box 默认按 1.12+ 的新写法生成（旧写法在 1.14 移除），UA 能看出是 1.12 以下的老客户端时自动用旧写法。
- **订阅地址不变**：`/sub?token=…`（及 `&b64` `&clash` `&sb` `&surge`、UA 自动识别）、`/<KEY>` 快速订阅与 edgetunnel 完全一致，token 算法相同，老用户无感迁移。

> **下载**：打包好的 `nicetunnel.zip`（主站）与 `nicetunnel-node.zip`（节点）见本仓库 [Releases](../../releases)；也可以自己 `node scripts/build.mjs` 构建。

## 相比 edgetunnel 的增强（一览）

数据面协议（VLESS / Trojan / SS、WS / gRPC / XHTTP）逐字沿用上游，下面都是在它之上的改动。

| 方面 | edgetunnel | nicetunnel |
|---|---|---|
| 账号 | 单号 | 一个主站 + 多个免费号的节点站点，按剩余额度与消耗节奏分配节点 |
| 用量 | 无 | 自动轮询各号当日请求数；Account ID 自动获取；批量导入、多选批量操作 |
| 节点检测 | 无 | 后台一键检测所有节点：域名、UUID、版本、出站连接方式、节点自报运行统计；坏节点自动不再分配 |
| 地区路由 | 无 | 订阅只放"地区"，连接时才选具体链式节点；健康反馈、拨号失败自动换台、SSTP 竞速、种子候选加快建连 |
| SSTP 链式代理 | 不应答保活（十几秒断）、不校验序号、无流控 | 应答 SSTP/PPP 保活、RST 立即结束、序号校验、收发流控；CPU 开销降到约 1/2（免费版每连接 CPU 有限） |
| 随机优选 | 每次请求全量重抽 | 同一时间窗各实例一致、渐进轮换、每节点不同 /24、倾向 443、可掺入已知可用地址、黑名单 |
| 订阅转换 | 依赖外部 SUBAPI | 内置 INI 解析与规则展开，配置缓存进 KV，订阅不连远程；原生 Clash / Surge / sing-box / 通用 |
| 客户端测速 | 按 INI | 按 INI；额度吃紧时自动放慢；补默认容差、`lazy` 测速 |
| Workers Paid | — | 只在主后台设置：地区条目只走付费域名，付费账号预算与轮询并发相应放大 |
| 防扫描 | 无 | 只按"凭据错误"按 IP 拦截（不误伤 XUDP）；节点伪装页零外部请求、其它路径返回真 nginx 式 404 |
| 后台 | 外部静态页 | 内嵌后台（国内可打开），9 个主题页 + 页内索引、改动才出现的保存栏、手机适配；可用 `LOGIN_PATH` 隐藏入口 |
| 自检与排障 | 无 | 配置自检（主站混进节点池、pages.dev 默认域名、凭据被填成后台密码、测速间隔过大等）；订阅响应头与 `/version` 自报构建号和生效设置 |
| 出站连接 | 只用 `request.fetcher` | 没有 `request.fetcher` 时自动改用 `cloudflare:sockets` |
| 省额度 | — | 节点站点不读写 KV；列表自适应缓存与失败退避；订阅热路径零 KV 写；日志批量限频写入 |
| 迁移 | — | 自动读取 edgetunnel 的 KV 配置、账号与 ADD 列表 |
| 测试 | 无 | 200+ 个自动化测试（`npm test`） |

注意：地区路由需要节点站点运行本项目的包（原版 edgetunnel 节点可作普通节点）；地区路由的链式连接受免费版 CPU 限制，大流量用途建议开 Workers Paid 或走普通节点。

## 架构

```
用户客户端 ──订阅──▶ 主站 main（Workers + KV + Cron）：订阅 / 后台 / 用量轮询
          ──代理──▶ 节点站点 node ×N（每个号一个 Pages，无 KV）：只跑协议 + 伪装页
```

同一个 `_worker.js` 自动判断角色：绑定了 KV 就是主站，否则是节点（可用 `MODE=main|node` 强制）。

## 部署

### 1. 构建（默认 edt 风格：保留注释 + 特征码隐藏）

```bash
npm install
npm run build                      # 全量包 + 纯节点包（均在 dist/）
npm run build -- --style=obf       # 压缩混淆风格：体积最小
npm run build -- --no-trailer      # 不追加尾部注释块（产物约 0.6MB，gzip 约 0.2MB）
npm run build -- --no-obfuscate    # 仅排查构建问题时使用：不隐藏、不混淆
npm run build -- --no-extras       # zip 里只放 _worker.js
```

> **edt 风格（默认）**：保留全部注释与可读结构，只把「特征码」按上游 cmliu/edgetunnel 的做法换成运行时表达式——`String.fromCharCode(...)` 计算项目名、作者标识、协议名等，文件里不再出现这些明文；同时按上游发布文件的形态附上尾部注释块。产物约 5.3MB（gzip 约 1.1MB），与上游发布文件（5.0MB）同一量级。**免费版 Workers 有 1MB 压缩体积上限**，主站若部署在 Workers 且超限，请加 `--no-trailer`（产物 0.6MB / gzip 0.2MB）。
>
> **obf 风格**：Terser AST 压缩 + javascript-obfuscator（标识符改名、Base64 字符串表），体积最小；关闭控制流平坦化、RC4、反调试、死代码注入等高开销功能，不修改对象属性名与外部接口。
>
> 两种风格都不改变运行逻辑：`npm run verify` 会把 `src/index.js` 与 `dist/_worker.js` 的对外响应逐路径比对。

> **zip 里有什么**：全量包 `nicetunnel.zip` 含 `_worker.js`、本项目的 `LICENSE` / `NOTICE.md` / `wrangler.toml` 和发布静态文件；纯节点包 `nicetunnel-node.zip` 只含数据面 `_worker.js` 与许可文件，不含后台、订阅、账号 API 或 Cron。两种包的数据面协议一致。

### 2. 节点站点（每个号一个）

1. Cloudflare 控制台 → Workers 和 Pages → 创建 Pages → 直接上传，推荐上传 `dist/nicetunnel-node.zip`（纯节点包）。也可继续上传全量 `dist/nicetunnel.zip`，两者在无 KV 时的数据面行为一致。
2. 环境变量只需要一个：**`UUID`（所有站点必须相同，主站后台「概览 → 节点站点（互联）」里可以直接复制）**。不需要设置 `ADMIN`。
3. 绑定自定义域名，如 `vp2.example.com`。**不要绑定 KV。**

**主站升级时需要重新部署节点吗？通常不需要。** 节点站点只依赖一份很小的「数据面契约」（见 `src/dataplane/contract.js`、`docs/DESIGN.md` §10）：UUID、订阅里的路径格式、`/version` 接口。只要契约没变（`/version` 返回的 `Dataplane` 版本号不低于主站要求），节点上可以继续跑旧版 `_worker.js`，只升级主站。后台「账号」页的「检测节点」按钮会在你的浏览器里直接访问每个节点，显示：域名是否生效、UUID 是否一致、数据面版本是否落后（每个节点多 1 次请求，不占主站额度）。

### 3. 主站

1. 创建 Worker，粘贴 `_worker.js`（或 `wrangler deploy`，见 `wrangler.toml`）。
2. 绑定 KV，变量名 `KV`。
3. 变量：`ADMIN`（后台密码）、`UUID`（与节点相同）、`KEY`（可选，快速订阅路径）、`HOST`（可选）。
4. 触发器 → Cron：`*/5 * * * *`。
5. 绑定域名，打开 `https://主站域名/admin` 登录。

> 主站也可以用 Pages 部署（Pages 没有 Cron），这时用量在订阅请求时"懒刷新"（后台异步，不阻塞订阅）。

### 4. 后台配置

- **脚本批量管理账号**：不想在网页里一个个填，可以用命令行脚本（用管理员密码做 Bearer 鉴权，幂等、不重复）：`NT_URL=https://主站 NT_PASSWORD=密码 node scripts/nt-accounts.mjs add --file accounts.txt --poll`。也可以直接调用 `POST /admin/api/accounts/upsert`，见 `docs/API.md` §6。
- **账号**：每个号一行导入 `节点域名,AccountID,APIToken[,备注]`（API Token 只需 *Account Analytics: Read* 权限），或 `域名,邮箱,GlobalAPIKey`。也可以直接导入旧用量面板的 `usage_config.json`。
- **额度**：Workers Paid、用量轮询、按额度分配、未纳入账号管理的节点域名——所有"额度怎么算、怎么分"的设置都在这一页。
- **节点来源**：优质来源填 gate 的 `https://…/nodes.txt?port=443`；"优选订阅"可填多个优选 URL（每行一个）；兜底随机优选按需调整数量、已知可用地址比例、端口、轮换比例。
- **检测工具**：后台「检测工具」页显示 Cloudflare 看到的你的 IP / ASN / 运营商 / 接入点，以及订阅据此自适应的结果；还可检测 SOCKS5/HTTP/HTTPS/TURN/SSTP 代理和优选 URL 是否可用。
- **订阅与规则**：填 INI 地址（默认是作者的 `subconfig2.ini`），点「获取并保存」把转换配置下载进 KV；之后订阅只读缓存，**不会再连远程**。规则模式 `expand`（规则直接写进配置）或 `provider`（客户端自己拉规则）。「自动更新转换配置」关掉后，只有再点「获取并保存」才会更新。

### 后台演示站（已不再维护）

> 演示站只在当时的版本上做过，之后不再随后台更新；`npm run demo` 仍可生成，但页面可能与最新后台不一致。

`npm run demo`（即 `node scripts/build-demo.mjs`）生成纯静态的演示站：`dist/demo/` 文件夹和 `dist/nicetunnel-demo.zip`。在 Cloudflare Pages 新建项目 → 直接上传这个文件夹或 zip 即可，不需要环境变量、不需要 KV。

- 页面就是真实的后台；`demo/mock.js` 在浏览器里模拟后台接口，**不连接任何服务器**，所有改动只保存在访问者自己的浏览器（localStorage），每个人看到的都是自己的一份。
- 设置清洗、账号合并、额度分配、配置自检用的是项目里的真实模块，所以改设置、改账号后概览和自检的变化与真后台一致。
- 内置演示数据覆盖各种状态：正常 / 偏低 / 耗尽 / 过期 / 轮询失败 / 需要手填 Account ID（填上再轮询就会恢复）/ 没填凭据 / 停用 / 付费账号 / pages.dev 默认域名；"检测节点"会给出正常、版本落后、edt 原版、读不到、UUID 不符、不可达、改用 cloudflare:sockets 等所有结果。
- 页面顶部横幅里的"恢复初始演示数据"可以随时重来；「系统 → 全部重置」也会恢复演示数据。

## 从 edgetunnel 迁移

主站首次启动时会读取 KV 里 edgetunnel 的 `config.json` / `tg.json` / `cf.json` / `ADD.txt`，自动转换为新配置（旧键只读不删，可随时切回）。旧的 `HOSTS` 会作为"未纳入管理的域名"继续参与分配，导入账号后即可按额度分配。

## 环境变量

| 变量 | 说明 |
|---|---|
| `ADMIN` | 后台密码（只有主站需要，**必须设置**）。主站没设 `ADMIN` 时后台不开放（不会像 edgetunnel 那样回退成 `UUID` / `KEY`——它们写在订阅里，会被拿来登录后台、导出所有 CF Token）；订阅照常可用。节点站点不需要 |
| `UUID` | 固定 UUID，所有站点一致 |
| `KEY` | 快速订阅路径 `/<KEY>`；也参与 UUID/cookie 推导 |
| `HOST` | 订阅 token 绑定的域名（多个取第一个） |
| `MODE` | `auto`(默认) / `main` / `node` |
| `PROXYIP` | 默认反代 IP（节点站点生效） |
| `GO2SOCKS5` | 追加 SOCKS5 白名单 |
| `URL` | 伪装页：`nginx`(默认) / `1101` / 任意网址 |
| `DEBUG`、`TCP_CONCURRENT_DIAL`、`PROXY_CONCURRENT_DIAL`、`PRELOAD_RACE_DIAL` | 数据面调优（与 edgetunnel 相同；**节点站点要在各自的环境变量里设置**） |
| `CHAIN_TIMEOUT`、`CHAIN_FAILOVER`、`CHAIN_RACE` | 地区路由链路：单步超时毫秒（默认 5999）、拨号失败后再换几台（默认 1）、SSTP 同时拨几台取最快（默认 2，设 1 关闭）。都在节点站点设置，不耗额外请求额度 |
| `LOGIN_PATH` | （主站，可选）隐藏后台入口：设为一串只有你知道的路径（如 `door-7f3k9`）后，登录页只在 `/door-7f3k9`；未登录访问 `/login`、`/admin`、`/admin/api/*` 一律返回 nginx 404。已登录会话和带 `Authorization: Bearer` 的脚本不受影响 |
| `GUARD` | 扫描/爆破防护，默认开；设 `0` 关闭（见下文"减少节点特征"） |
| `CHAIN_TIMEOUT` | 链式代理拨号的连接/读写超时，默认 `5999`（毫秒）。调小＝坏节点更快被判死，调大＝弱网更容易成功 |
| `CHAIN_FAILOVER` | 地区路由的链路故障转移次数，默认 `1`（当前节点拨不通时最多再换 1 台重试）；`0` 关闭，行为与 edgetunnel 完全一致 |
| `BEST_SUB` | 开启"优选订阅生成器"模式（同 edgetunnel） |

## 地区路由（可选，默认关闭）

适合"节点寿命很短、列表高频变化"的来源（例如 VPN Gate，每 10 分钟换一批）。开启后：

- **订阅里只有"地区"**（日本、韩国……），客户端选地区、不选具体节点。订阅只在"地区集合"变化时才变，不再跟着列表每 10 分钟更新，客户端更新间隔可以放到几小时。
- **真实节点在每条连接建立时才选**：节点站点读取你配置的列表（实例内缓存 180 秒；列表内容长期不变时缓存会自动放大，最长约 24 分钟），在前 K 台（默认 10）里用会合哈希挑一台——同一用户长期稳定在同一台，不同用户分散到不同节点；列表增删节点时只有被影响的那部分用户换节点。
- **带健康反馈**：某台链式节点拨号失败会在实例内被标记，5 分钟内排到最后（重连不会再撞同一台死节点）；拨号成功过的节点优先。选路时还会优先握手更轻、更稳的协议（`socks5`/`http` > `https` > `sstp`/`turn`），列表原有的延迟排序作为同等条件下的次序。
- **拨不通会自动换一台**：地区路由会把排好序的候选链随连接一起传进数据面，当前这台拨不通时先换下一台重试（默认 1 次，见 `CHAIN_FAILOVER`），而不是立刻断开客户端——这是"用得上但老是突然断"的主要修复点。
- **省额度**：订阅条目少了，客户端测速（每节点 1 次请求）成倍减少；列表拉取有自适应 TTL 与失败退避（失败后不再按固定频率反复外拉），主站与节点站的请求量都更低。
- **通用**：不绑定任何来源。后台「节点来源 → 地区路由」里填列表 URL（可多个）和地区规则（正则，第 1 组=地区，第 2 组=类型；留空则取名称里第一个 `- _` 空格或数字之前的部分）。
- 客户端里每个"地区+类型"一个条目，名字形如 `【家宽】日本`、`【机房】美国`（类型显示名在"类型显示名"里设置，默认 `住宅=家宽`；名称模板默认 `【{kind}】{region}`）。条目顺序固定（先按类型显示名的书写顺序，再按地区名），不随节点数变化。只想要某类时在"只保留这些类型"里填 `住宅`。
- ⚠ **INI 里按名字匹配的组要同步改**：比如原来匹配 `住宅` 的组成员正则要改成 `家宽`，否则该组会是空的（回退 DIRECT）。
- 列表每行：`入口地址#名称$sstp://用户:密码@主机:端口`（也支持 `socks5 / http / https / turn`；没有入口地址的行，入口由随机优选池补）。
- ⚠ 开启后**所有节点站点必须运行本项目的 `_worker.js`**（原版 edgetunnel 不认识地区路由路径）。它与"优质来源"相互独立，同一份列表不要两处都填。
- 已建立的连接在上游节点中途掉线时仍会断，要等客户端重连（这一点和不用地区路由时一样）；但**新连接拨号失败**已经会先换候选节点，不再直接把客户端踢下线。
- **建连提速**：主站把每个地区的 4 台候选（"种子"）写进订阅路径。节点站点的新实例等列表最多 0.8 秒，超时或拉取失败就先用种子拨号，列表在后台拉；连 VPN 服务器、等它第一个响应各最多 3 秒，死节点能在客户端测速超时前换下一台。
- ⚠ **免费版的 CPU 限制**：SSTP 链路要在 Worker 里跑整套 VPN/TCP，每 MB 要几毫秒 CPU；免费版每个连接只有 10ms，传 1~2MB 就会被掐断（客户端表现为"用着用着断"、ECONNRESET）。解决办法见下一节。

## Workers Paid（付费版，可选）

付费版每个请求的 CPU 上限是 30 秒（免费版 10ms），每月含 1000 万次请求，账号级 $5/月。地区路由的链式连接最需要它；普通节点在免费版上就够用。

**只需在主后台设置，节点站点不用改、不用重新部署**：

1. 在 Cloudflare 面板给某个号开通 Workers Paid（最省：只开主号）。
2. 后台「额度」页 → Workers Paid：勾选 **主号已开通 Workers Paid**。节点账号开了付费的，在「账号」页的账号表里勾 **付费**。
3. 默认 **地区条目只分配给付费域名**（主站自己 + 勾了付费的账号），按剩余预算分摊；普通节点照常用所有免费账号分摊，不占主站额度。没有任何付费域名时自动回退为分配给全部节点。
4. 主站绑定了多个域名时，可在"主站承载地区条目的域名"里固定用哪个（留空 = 生成订阅时访问的那个）。

其它适配（Workers Paid）：付费账号的每日预算按 `每月 1000 万 ÷ 30 ≈ 33 万` 计（可改，账号自己填了每日额度时以账号为准）；主号付费时一次用量轮询的子请求上限从 45 提到 400，账号多也能一轮轮完；"检测节点"会把承载地区条目的主站域名一起检测；概览的 KV 写入额度按付费版显示。客户端需要重新拉一次订阅，地区条目才会换到付费域名上。

## 多用户专属链接（可选，默认关闭）

原有订阅链接不变；另外给每个人发一条自己的永久链接，可以封禁、单独设置并行客户端数、看在线和用量。

1. 后台「系统」→ 多用户专属链接：勾 **开启多用户**，设默认并行数（默认 2，0 = 不限）。左侧出现「用户」页。
2. 「用户」页 → 节点账号配置：每个节点账号点 **自动配置**。它会用账号的 Token 建 KV 命名空间 `nicetunnel-mu`、给 Pages 项目加绑定 `NT_MU`（KV）和 `NT_AE`（Analytics Engine，数据集 `nicetunnel_mu`）并重新部署。Token 需要 **Workers KV Storage: Edit**、**Cloudflare Pages: Edit**、**Account Analytics: Read**。自动配置失败时按这些名字在 Pages「设置 → 绑定」里手动加，重新部署，再勾「已手动绑定」。节点代码要用这一版（能力 `multi-user@1`）。
   - **直接上传的项目**（控制台上传 zip 部署的，最常见）：Cloudflare 不允许用 API 重试这类部署，绑定加好后要再上传一次代码才生效。在 Pages 控制台重新上传节点包，或者在本机运行：
     `CF_API_TOKEN=<节点账号 Token> node scripts/deploy-node.mjs --account <AccountID> --host <节点域名> --file dist/_worker.js`（节点上部署的是哪个包就传哪个：全量包 `dist/_worker.js` 或纯节点包 `dist/_worker.node.js`）。
     上传完再点一次「自动配置」，会自动检测到新部署并变为就绪。
   - 项目被 Cloudflare 封禁（abuse）时会标出来，不会再把用户分到这个账号。
   - **Analytics Engine 要先在每个账号开通一次**（控制台 Workers & Pages → Analytics Engine，免费）。没开通时带着 `NT_AE` 绑定部署会失败（"You need to enable Analytics Engine"）。自动配置会先探测：用不了 AE 就只加 `NT_MU`（封禁照常生效，这个账号没有在线统计和并行限制）；已经因此部署失败的会自动去掉 `NT_AE`。开通后再点一次「自动配置」会补回，再上传一次即可。
3. 主站 Worker 建议再加一个 Cron 触发器 `* * * * *`（保留 `*/5 * * * *`）：每分钟汇总一次在线情况。不加也能用，最慢 5 分钟同步一次。
4. 「用户」页 → 批量生成，复制链接发给用户。

工作方式：用户的节点路径带前缀 `/_u<ID>`，他的 UUID / 密码由主站的随机密钥签出来，节点自己就能验证，不发请求。节点把"用户 + IP 标记"写进本账号的 Analytics Engine；主站定时查各账号、算出谁超限，把可用用户名单和超限用户允许的 IP 写进各节点账号的 KV，节点每分钟读一次。

- **封禁提示**：被封用户更新订阅时，拿到的是一份只有一个提示节点的配置（节点名就是提示语，可在「用户」页 → 基本设置里改，后面自动带上解封时间或"永久"；规则全直连，不会断网），浏览器打开则显示提示页——不再只是一个客户端看不懂的 403。删除的用户链接仍然返回伪装页。
- **生效时间**：封禁 / 删除约 1~2 分钟（立即下发）；并行超限约 2~7 分钟——超限名单只变化时最快 5 分钟下发一次、每天最多 200 次，免得写满 KV 每天 1000 次的免费写入额度。被拦的是多出来设备的**新连接**，已经建好的连接要等它断开。
- **并行数怎么算**：同时在线的不同 IP（IPv6 按 /64），先连上的保留。同一台设备同时有 IPv4 和 IPv6 会算 2 个，手机切换网络时旧 IP 约 5 分钟后释放，所以一个人建议设 2。
- **额度**：节点不多发请求；Analytics Engine 每个账号每天免费写 10 万条、查 1 万次，一对"用户 + IP"在线 1 小时约写 30 条；主站每次同步每个账号 1 次查询，状态有变化才写 KV。
- 用户订阅只分配到配置好的账号；一个都没有时用主站自己。主站自己承载的流量不计入在线统计。
- **密钥**：订阅链接用主站 KV 里的主密钥签名；节点账号 KV 里只有由它派生的节点密钥（只能算用户 UUID），节点账号泄露也伪造不了订阅链接。
- **原来的共享订阅仍然有效**：不带 `/_u` 前缀的连接照旧用共享 UUID，封禁和并行限制管不到它。原共享链接发出去过的话，要换 UUID（主站和所有节点一起改）才能收回。
- **Token 权限**：自动配置要求节点 Token 有 KV 编辑和 Pages 编辑权限，比只读用量的 Token 权限大；主站后台一旦失守，影响也更大。配置完可以把这两项权限去掉（之后的下发只需要 KV 写入：保留 Workers KV Storage: Edit 即可）。

### 封禁时长与自动封禁

- **手动封禁**：「用户」页选时长（默认永久，可选 1 小时 / 1 天 / 3 天 / 7 天 / 30 天）再点封禁；到期自动解封，不需要再写一次用户名单。被封用户看到的提示自动带上"几月几日几点解封，剩余约多久"或"永久"。
- **自动封禁**（默认关闭，「用户」页 → 自动封禁）：每隔几分钟（默认 10）检查一次，任一条开启的规则在"统计多少小时内"达到阈值就封禁。
  | 规则 | 数据来源 |
  |---|---|
  | 超过并行上限的次数 | 同步记录（下发的超限名单里出现一次算一次） |
  | 连接数（≈ 节点 Worker 请求数） | 节点账号的 Analytics Engine |
  | 使用的不同 IP 数、连到的不同机房数（链接被分享 / 多地同时用） | 节点账号的 Analytics Engine |
  | 订阅更新次数、拉订阅的不同 IP 数（链接外泄） | 主站的 Analytics Engine：主站 Worker 需绑定 `NT_AE`（数据集 `nicetunnel_mu`），没绑这两条规则就没有数据 |
- **阶梯处罚**：统计周期内第 1 次违规封 30 秒、第 2 次 5 分钟、第 3 次 24 小时、第 4 次 72 小时、第 5 次起永久（可改）；统计周期（默认 168 小时）过了违规次数清零。用户页能看到每个人的违规次数，也可以手动清零。
- **不会一解封就再被封**：封禁或解封之后，规则只算之后的数据（按用户单独查询）。
- **额度**：检查跟着 Cron 跑，不增加 Worker 请求；查询用的是各节点账号（和主站账号）自己的 Analytics Engine 额度；只在封禁 / 解封时写 KV。被封用户拉订阅也受每分钟限速，客户端按剩余封禁时长（1~24 小时）才会再来拉。被封用户的旧配置如果还在反复连节点，那部分仍会消耗节点的请求额度，直到他更新订阅。

## 一键导入

- **概览页「一键导入」**：Clash 系 / sing-box / Shadowrocket / Stash / Surge / Hiddify 的导入按钮，外加订阅二维码（另一台设备扫码）。
- **专属订阅落地页**：用户在浏览器里打开自己的专属链接，看到的是导入页（按钮 + 二维码 + 复制），不是一堆配置文本；代理客户端拉同一个链接照常拿订阅。带了 `target` 等格式参数时也照常给订阅。后台「用户」页每行有「导入页」按钮。
- 二维码在本地生成，页面不加载任何外部资源。

## 家宽订阅（客户端链式，可选，默认关闭）

思路来自 [cfnew](https://github.com/byjoey/cfnew) 的"家宽链式"：出口换成 VPN Gate 志愿者的住宅宽带，适合一见机房 IP 就弹验证码的网站。

- 链路：`客户端 → 你的 CF 节点 → 住宅宽带（OpenVPN）→ 目标站`。OpenVPN 由客户端自己跑（mihomo 的 `type: openvpn` + `dialer-proxy`），Worker 只做普通 TCP 转发——和「地区路由」（Worker 里跑 SSTP）不同，**免费版也不会被掐断**。
- 开启：后台「节点来源」→ 家宽，勾启用；订阅链接后面加 `&target=home`（专属链接同样可以）。概览页和用户落地页会多一个「Clash 家宽」导入按钮。
- 列表由 Cron 每小时从 VPN Gate 拉一次（约 1MB，只留 TCP 节点、去掉 VPN Gate 自营的机房服务器、按得分取前 N 个）；可以在后台点「立即刷新列表」。列表还没拉到时订阅返回 503，客户端会继续用上一份。
- 只有 **mihomo 1.19.25 以上** 能用（Clash Verge Rev / FlClash / Clash Meta for Android），所以只出 Clash 格式；只走 TCP。前置只用你的 TLS 节点。
- **不支持的客户端**（sing-box、Shadowrocket、Stash、Surge、v2rayN、Clash Premium，或 UA 里写明内核低于 1.19.25 的 mihomo）拿家宽链接时，不会拿到一份加载不了的配置，而是**退回它能用的普通订阅**（照常有普通节点，只是没有家宽），响应头 `X-NT-Home: fallback; 原因` 写明原因。UA 不带内核版本的 mihomo 系客户端按支持处理；如果内核实际太旧导致加载失败，升级客户端即可。
- 节点是志愿者共享的，掉线是常态（大约一半能通）；`🏠 家宽自动` 会自动选最快的可用节点（测速时限 15 秒），想挑国家在 `🏠 家宽节点` 里手选。速度取决于对方家里的上传。

## 自建 ProxyIP（访问套了 CF 的网站更快更稳）

Worker 连不了 Cloudflare 的 IP，访问套了 CF 的网站（ChatGPT、X 等）要经 ProxyIP 中转。不设 `PROXYIP` 时用的是公共反代，多人共用，常常又远又慢。最有效的办法是在**主站**设一个离用户近、稳定的 `PROXYIP`（会自动写进所有节点的订阅路径）。手里有 VPS 的话可以自建：在 VPS 上用 Reality / 反代把 443 端口转发到 Cloudflare（IPv6 VPS 也可以），然后把 VPS 地址填进 `PROXYIP`。

## KV 用量

- **读（免费版每天 10 万次）**：订阅热路径的设置 / 账号 / 用量 / 转换配置 / 规则块都先走实例内存（30 秒 ~ 10 分钟），所以同一实例里 300 次订阅请求额外读 KV 为 0 次；一个新实例冷启动最多读 6 次。即使有几百个实例也远低于上限。
- **写（免费版每天 1000 次，是真正紧的）**：订阅热路径从不写；只有 Cron / 后台操作会写，且内容没变就不写。
- 读写 KV 不占 Workers 的 10 万次请求额度；从 GitHub 等地拉取转换配置、规则列表是子请求，同样不占。

## 订阅怎么摊额度

- 每次拉订阅 = 主站账号 1 次请求。"所有用户共用一个链接"时，订阅请求全部算在主站那个号上，代理流量才摊到各节点号。客户端更新间隔（后台"订阅"页）是最大的杠杆：1000 个客户端每 10 分钟拉一次≈每天 14.4 万次，超过单号 10 万；改成每小时≈2.4 万。
- 前面再加一个"负载均衡 Worker"不会省：它自己每次被调用也算 1 次请求，只是把压力挪到别的号。真要分摊，可以在多个号上各部署一个带 KV 的主站、把链接分发给不同用户群。

## 排障：确认线上跑的是哪一版、生效的是什么设置

- **构建号**：每次构建都会算出一个 8 位构建号（同样的代码得到同样的号），构建时会打印。线上可以在三个地方看到：后台左上角（`v0.1.0 · 075a81ed`）、`/version?uuid=…` 返回的 `Build` 字段、订阅响应头 `X-NT-Build`。和构建时打印的对一下，就知道线上是不是最新。
- **订阅自报生效设置**：订阅响应头 `X-NT-Opts: agg=1;tmin=0;regions=1;random=1`，分别是：随机优选聚合是否开启、测速间隔下限（0 = 按 INI）、地区路由是否开启、随机优选是否开启；额度吃紧、测速正在放慢时还会多一项 `tight=0~1`。订阅链接本身有 token 保护，这些不是敏感信息。查看：
  ```bash
  curl -s -D - -o /dev/null "https://主站域名/sub?token=你的token&clash" | grep -i "x-nt-"
  ```
- **旧设置不会自动用上新默认值**：KV 里保存的是旧版本第一次运行时写下的完整设置快照，已有字段会一直保持旧值，新默认值只对"新增字段"生效。需要改的话到后台对应页面手动改；本项目把确定要升级的旧默认值写成了迁移（目前：测速间隔下限的旧默认 600 → 0（按 INI）、url-test 默认容差 100 → 50；地区路由候选数 / 粘性 / 列表缓存的旧默认）。
- **地区规则留空 = 自动**：主站用默认规则（形如 `日本-住宅-01`）识别出类型，并把规则写进订阅路径，节点（新旧版本）按路径里的规则解析，所以调整规则不需要升级节点。

## 降低暴露与封禁风险

- **节点使用 `nicetunnel-node.zip`**：只部署数据面，避免在节点包中携带主站后台、订阅和账号管理代码。主站仍使用全量包。
- **保留正常伪装响应**：普通 GET、错误 UUID 的 `/version` 与 edgetunnel 一样返回 nginx 伪装页。不要用统一 WAF 拦截页回应所有扫描，这本身就是明显且稳定的站点特征。
- **WAF 只处理明确异常流量**：优先按 IP / ASN / 路径做限速或临时拦截，不要一刀切拦截所有非 WebSocket 请求；XHTTP/gRPC 本来就是 POST，伪装页和节点检测也依赖普通请求。
- **保护互联凭据**：正确 UUID 的 `/version` 会返回数据面能力信息，订阅和 UUID 只交给需要使用的人；泄漏后应整体更换并重新部署所有节点。代码混淆不能隐藏线上流量，也不能保证域名或账号不被封。
- **地区列表使用 HTTPS**：当前实现已在内容不变时逐步降低拉取频率，并在失败后退避；不要为了“新鲜”把 `ttlSeconds` 调得很小，那会增加周期性外联与额度消耗。

## 省额度建议

1. **测速间隔是大头**：客户端 `url-test` / `fallback` / `load-balance` 组每隔 interval 秒对组里每个节点发一次请求，每次都算节点 Worker 的 1 次请求。以 70 个节点、300 秒间隔计，一个正在使用的客户端一天约 2 万次。本项目**默认完全按 INI 里每个组写的间隔**（随机优选 300 秒、故障转移 / 负载均衡 180 秒），并让测速组带 `lazy`（组没被使用时不测速）。以前默认把所有组拉到至少 600 秒（最长 1800 秒），变慢或失效的 CF IP 要 10~30 分钟才会被换掉，客户端表现为卡、慢，所以改回按 INI；想更省可在「订阅与规则 → 客户端测速」里设"测速间隔下限"。
   **额度吃紧时自动放慢（默认开，`sub.testIntervalAuto`）**：每次生成订阅时，主站按号池"剩余额度 ÷ (预算 × 今天剩余时间占比)"算余量比 h。h ≥ 1（够用）时各组完全按 INI；0.5 < h < 1 时各组间隔从自己的 INI 值线性拉长；h ≤ 0.5（吃紧）拉到 `testIntervalCeil`（默认 1800 秒）。客户端按 `Profile-Update-Interval`（默认 1 小时）更新订阅时拿到新间隔；订阅响应头 `X-NT-Opts` 里的 `tight` 表示放慢程度。
   测速只消耗**节点账号**的额度（每节点每次 1 次请求），不占主站；地区节点的每次测速还会在节点上完成一次 SSTP 登录（不耗 Cloudflare 额度，但会占用对方 VPN 服务器的会话）。
2. **用 WS 传输**：一条 WS 连接只算 1 次请求；XHTTP/gRPC 的计数方式未在真机上核实。
3. **WAF 只拦明确异常来源**：确有需要时按攻击 IP / ASN / 具体扫描路径做限速或临时拦截。不要再用“拦截所有非 WS 请求”的规则：它会让 XHTTP/gRPC、伪装页和节点检测失效，还会形成统一拦截页指纹。

### 断线与节点切换（地区路由 / 测速组）

- **地区节点选择**：用会合哈希挑节点——节点列表增减时，只有被移走那台的用户会换节点，其余人不动；每个客户端 IP 段的稳定期切换时间错开，不会所有人同一分钟集体换。拨号失败的节点在本 isolate 内冷却 5 分钟，成功过的节点优先；同类条件下优先更稳的协议。稳定期默认 30 分钟（`stickyMinutes`），设为 0 则每条连接随机。
- **拨号失败先换候选**：地区路由的连接会把候选链按同样顺序带进数据面，第一台拨不通就换下一台重试，仍失败才断开；客户端看到的"刚连上就掉"大幅减少。
- **url-test 默认容差**：设置 `sub.tolerance`（默认 50 毫秒，和常用 INI 一致）。INI 里没写容差的 url-test 组会补上，新节点比当前节点快不到这个值就不切换，减少相近节点之间来回切换造成的连接断续；太大会让客户端停在变慢的节点上。设为 0 则不加。
- **SSTP 链路修正（地区路由断连的主因）**：上游的 SSTP 实现不应答服务端保活（SSTP ECHO / PPP LCP Echo），VPN Gate 用的 SoftEther 收不到应答会在十几秒内断开会话，客户端表现为"连上了也断断续续、突然断开"。现在节点会按协议应答，并且：读空闲超时从 60 秒放宽到 5 分钟；对端 RST 或断开时立即结束（不再挂到超时，故障转移更快）；校验 TCP 序号，重复或乱序的段不再拼进数据流；按客户端读取速度缩小接收窗口（慢客户端不会把 isolate 内存撑爆、连累同 isolate 的其他连接）；SYN 带 MSS=1400（原来对端只能按 536 字节分段，包数多约 2.6 倍）。上传方向也遵守对端通告窗口（原来不看窗口也不重传，上传快时超窗的段被丢、连接静默卡死），窗口 60 秒无进展会明确断开。这些都在节点站点运行，**需要把节点站点换成新的 `_worker.js`**；后台"检测节点"会把还没更新的节点标为"缺少新能力：sstp-keepalive@1"。
- **地区列表过期不再阻塞连接**：列表缓存过期不久时先用旧列表、后台刷新，不会让某次连接卡在拉列表上（最长 3 秒，客户端测速显示超时）。
- **SSTP 竞速**：地区路由连接时同时拨两台 SSTP 候选，先握手成功的用、另一条关掉。VPN Gate 握手失败率高、耗时波动大，竞速能明显减少超时和首包等待。仍是同一个 Worker 请求，不多耗额度；代价是多开一个 VPN 会话。环境变量 `CHAIN_RACE=1` 关闭。
- **主站额度**：`/<KEY>` 快速订阅直接返回内容，不再 302 跳转（客户端每次更新订阅只算主站 1 次请求，原来 2 次）；后台和登录页内联图标，浏览器不再请求 `/favicon.ico`。

### 减少节点特征（防扫描、防滥用）

都不读写 KV、不外拉，不额外消耗额度：

- **伪装页像真实 nginx**：只有 `/` 是 nginx 欢迎页，其它路径（`/admin`、`/sub`、`/.env`、`/wp-login.php`……）都返回 nginx 原样的 404 页。原来任意路径都回 200 欢迎页，扫描器很容易认出"这不是真 nginx"。主站对未授权请求同样如此。
- **认证失败限流**：同一 IP 在 10 分钟内首包认证失败（UUID/密码不对或首包无法解析）5 次，之后 30 分钟内它的代理请求直接拿伪装页，不再升级 WebSocket。扫描器第二次探测看不到代理特征，爆破也无法继续。正确 UUID 的客户端不会触发；计数只在单个 isolate 内存里。环境变量 `GUARD=0` 关闭。
- **隐藏后台入口**（主站可选）：环境变量 `LOGIN_PATH`，见上表。设了之后请把 `/<LOGIN_PATH>` 收藏好；会话过期时后台页会自动跳回这个入口。
- **仍然存在的特征**：没开 0-RTT 时，任何人对任意路径发 WebSocket 升级都会先得到 101（UUID 要等第一个数据包才能校验）。开启后台"0-RTT"（`ed=2560`）后客户端会把首包放进握手头里；目前仍按兼容方式处理，没有强制拒绝无首包的升级，以免不支持 0-RTT 的客户端连不上。
- **检测节点结果用于分配（互联）**：后台账号页点"检测节点"后，结果会自动交给主站（一次请求、一次 KV 写，3 天内有效，重新检测即更新）：不可达 / UUID 不符的节点不再分配进订阅；edgetunnel 原版或旧数据面（不认识地区路由路径）的节点不承载地区条目——否则这类节点上的地区节点会 100% 连不上。排除后没有可用节点时自动回退原池。检测在浏览器里直接访问各节点的 `/version`，不占主站额度，每台节点 1~2 次请求。
- **`LOGIN_PATH`（隐藏后台入口）**：设置后登录页只在 `/<LOGIN_PATH>`。不要和 `KEY` 设成同一个值——同值时会按访问者区分（浏览器→登录页，代理客户端→订阅），但 UA 像浏览器的客户端会拿到登录页 HTML，报 `Unexpected scalar at node end` 之类的 YAML 错误；后台自检会提示。
- **主站 PROXYIP 下发给节点**：后台"反代 IP"为 `auto` 时，原来每个站点用自己的环境变量 `PROXYIP`，没设就退回公共默认反代（多人共用，常慢或不可用）。主站设了而节点没设，就会出现"主站的节点好用、节点账号的节点连不上 / 断"（套 Cloudflare 的网站只能经反代 IP 访问）。现在主站的 `PROXYIP` 会写进订阅里的节点路径，所有节点统一使用；后台明确填了反代 IP 时以后台为准。
- **扫描防护只封凭据错误**：防护（`GUARD`）只把 UUID / Trojan 密码不符算作认证失败。之前 mihomo / Xray 开 XUDP 时 UDP 走 Mux（上游回 "Invalid command"）等正常流量也被计数，普通用户几分钟就会被封 30 分钟。需要节点站点更新 `_worker.js`。
- **轮询 400 / 9106**：浏览器会把保存的后台密码自动填进账号页的 Token 密码框，保存后存进去的是后台密码，Cloudflare 报 `9106 Authentication failed`，真正的 Token 从未被使用。输入框已禁止自动填充；保存时与后台密码相同的凭据会被忽略；已经存错的账号会在后台自检里提示。Account ID 可以留空，轮询时自动获取并回填。
- **节点自报统计（排查断连）**：节点站点在内存里记录连接数、被防护拦截数、UUID/密码错误数、地区路由失败数、链路拨号成败与最近 12 条失败日志（不读写 KV、不额外消耗请求额度）。后台"检测节点"会一并取回，每个节点下面显示一行，例如"近 35 分钟：连接 820，链路 成功 140 / 失败 22，最近错误（12 秒前）：[反代连接] 本批连接失败: …"。只反映检测请求落到的那个运行实例，用来看趋势和最近的错误。没更新的节点会标"缺少新能力：guard-cred@1 node-stats@1"。
